# 企业级进销存管理微信小程序 — 升级改造实施方案

> **目标：** 将现有「药品盘点」小程序升级为覆盖采购、销售、库存、财务、客户全链路的企业级进销存管理系统。
>
> **架构：** 小程序前端（原生框架）+ 云函数 / 自建后端 API + MySQL/PostgreSQL 持久层，采用分层架构与领域驱动设计，前后端通过 HTTPS + JWT 鉴权通信。
>
> **技术栈：** 微信原生框架 + Vant Weapp UI 组件库 + ECharts 图表 + 后端 Node.js(Express/NestJS) 或 Java(Spring Boot) + Redis 缓存 + 消息队列

---

## 一、现状评估

### 1.1 现有资产

| 维度 | 现状 |
|------|------|
| 页面 | 6 个页面（首页、盘点、我的、登录、记录、库存查询） |
| 功能 | 药品扫码盘点、库存查询、盘点记录、用户登录 |
| 架构 | 小程序原生框架，无第三方 UI 库 |
| 数据 | Mock 数据驱动，无真实后端 |
| 配置 | 三环境自动检测（dev/test/prod） |
| 请求层 | 基础封装，含重试机制 |

### 1.2 差距分析

| 缺失能力 | 影响 |
|----------|------|
| 无采购管理模块 | 无法追踪进货、供应商 |
| 无销售管理模块 | 无法处理出库、订单 |
| 无财务管理 | 无法核算成本利润 |
| 无客户/供应商管理 | 上下游信息断层 |
| 无权限体系 | 无法区分角色（管理员/操作员/财务） |
| 无报表分析 | 缺乏决策数据支撑 |
| 无真实后端 | 无法持久化、无法多端协同 |
| 无消息推送 | 无法预警库存不足/效期临近 |

## 五、技术选型

### 5.1 小程序端

| 技术项 | 选型 | 理由 |
|--------|------|------|
| 框架 | 微信原生框架 | 现有项目基础，无需迁移成本 |
| UI 组件库 | **Vant Weapp** | 企业级组件丰富（表格、表单、弹窗、Stepper），维护活跃 |
| 图表 | **ECharts 微信小程序版** | 百度开源，支持折线/柱状/饼图/仪表盘 |
| 状态管理 | 自定义 Store + Storage | 小程序场景轻量即可，无需引入 MobX/Redux |
| 扫码 | wx.scanCode（已有） | 原生 API，稳定可靠 |
| 打印 | wx.createOffscreenCanvas → 蓝牙打印 | 小票/单据打印场景 |

### 5.2 后端

| 技术项 | 推荐方案 A | 推荐方案 B |
|--------|-----------|-----------|
| 语言/框架 | **Node.js + NestJS** | **Java + Spring Boot** |
| 数据库 | PostgreSQL | MySQL 8.0 |
| 缓存 | Redis | Redis |
| 文件存储 | 阿里云 OSS / 腾讯云 COS | 同左 |
| 消息队列 | RabbitMQ / RocketMQ | 同左 |
| 接口文档 | Swagger / OpenAPI 3.0 | 同左 |

**推荐方案 A（Node.js + NestJS）：**
- 与小程序前端同为 JavaScript 生态，团队学习成本低
- NestJS 提供模块化、依赖注入、守卫/拦截器，天然适合企业级架构
- 开发效率高，适合快速迭代

### 5.3 第三方服务

| 服务 | 用途 |
|------|------|
| 微信 OCR | 识别纸质单据上的文字（批号、有效期） |
| 腾讯云短信 | 验证码登录、审批通知 |
| 微信订阅消息 | 库存预警、效期提醒推送 |
| 微信支付 | 收款场景（如有零售场景） |

## 六、开发流程

### 6.1 总体阶段

```
Phase 0: 基础设施搭建（2 周）
  ├── 后端项目初始化（NestJS 脚手架 + 数据库迁移脚本）
  ├── CI/CD 流水线搭建（GitHub Actions / Jenkins）
  ├── 开发/测试/生产环境配置
  └── 代码规范 + ESLint + Prettier + Husky

Phase 1: 基础数据 + 权限体系（3 周）
  ├── 商品档案 CRUD
  ├── 供应商/客户档案 CRUD
  ├── 用户/角色/权限 RBAC
  └── 登录/鉴权（JWT + 微信登录）

Phase 2: 库存管理升级（3 周）
  ├── 现有盘点功能迁移至 inventory 模块
  ├── 库存台账（批次+库位维度）
  ├── 效期预警
  └── 调拨/报损报溢

Phase 3: 采购管理（4 周）
  ├── 采购订单 CRUD + 状态机
  ├── 采购入库（扫码验收）
  ├── 采购退货
  └── 应付款生成

Phase 4: 销售管理（4 周）
  ├── 销售订单 CRUD + 状态机
  ├── 销售出库（扫码发货）
  ├── 销售退货
  └── 应收款生成

Phase 5: 财务管理（3 周）
  ├── 应收应付台账
  ├── 收付款录入
  └── 成本核算

Phase 6: 报表分析（3 周）
  ├── 经营看板
  ├── 进销存报表
  └── 销售/采购趋势图

Phase 7: 消息通知 + 优化（2 周）
  ├── 订阅消息推送
  ├── 性能优化
  └── 离线能力增强

总计：约 24 周（6 个月）
```

### 6.2 迭代策略

- 每 2 周一个 Sprint
- 每个 Phase 结束进行演示评审
- Phase 2 完成后即可内部试用（MVP：库存管理 + 基础数据）
- Phase 4 完成后可对外灰度发布

## 七、质量保障

### 7.1 代码质量

| 措施 | 工具 |
|------|------|
| 代码规范 | ESLint + Prettier（小程序端用 eslint-config-wxapp） |
| 提交规范 | Commitlint + Conventional Commits |
| 代码审查 | PR Review 强制通过后方可合并 |
| 静态分析 | SonarQube（后端） |

### 7.2 测试策略

| 层级 | 覆盖目标 | 工具 |
|------|----------|------|
| 单元测试 | 后端 Service 层 ≥ 80% | Jest（NestJS）/ JUnit（Spring Boot） |
| 接口测试 | 所有 API 端点 | Supertest / Postman Collection |
| 小程序端测试 | 核心工具函数 | miniprogram-simulate + Jest |
| E2E 测试 | 核心业务流程 | 微信开发者工具自动化 + miniprogram-automator |
| 手工测试 | 每 Sprint 功能验收 | 测试用例清单 |

### 7.3 安全措施

| 层面 | 措施 |
|------|------|
| 传输层 | 全量 HTTPS，证书固定（SSL Pinning） |
| 鉴权 | JWT + Refresh Token，Token 有效期 2h |
| 数据 | 敏感字段 AES-256 加密存储，手机号/身份证脱敏展示 |
| 防注入 | 后端参数化查询，前端输入白名单校验 |
| 防越权 | 接口级权限校验（Guard），数据行级归属校验 |
| 日志 | 全量操作日志（谁 + 何时 + 做了什么 + IP） |
| 小程序 | AppID 绑定、代码加固上传、不硬编码密钥 |

### 7.4 性能优化

| 层面 | 措施 |
|------|------|
| 小程序 | 分包加载（主包 < 2MB）、图片懒加载、列表虚拟滚动 |
| 接口 | Redis 缓存热点数据（商品列表、供应商列表）、分页查询 |
| 数据库 | 索引优化（商品名称/条码/批号）、读写分离 |
| 图片 | CDN + WebP 格式 + 按需裁剪尺寸 |
